CLI 操作与退出码速查

命令入口：npx i18n-collect。所有命令都从已有 collection catalog 开始或产生它，绝不隐式越过安全边界。

命令矩阵

命令输入写入绝不做
collect已接入 loader/plugin 的 Webpack configdictionary、map、源 locale catalog/meta改应用源码、翻译、网络访问
translate源 catalog/meta + 项目 provider目标 locale catalog、translation-state运行 Webpack、改应用源码、携带厂商 SDK
replacecatalog/meta + adapter/runtime 证据默认无；--write 才改源码及相关 artifacts插 import、装依赖、改 bootstrap、默认写文件
run选中的 stages 与各自 flags被选 stage 的产物乱序执行、失败后继续

典型用法

npx i18n-collect collect --webpack-config webpack.config.js
npx i18n-collect translate --locale en --provider i18n/provider.js
npx i18n-collect replace --adapter js             # preview
npx i18n-collect replace --adapter js --write
npx i18n-collect run --collect --translate --replace --adapter js --write

退出码

码含义首要动作
0所选操作完成阅读 report；replace 仍可能只是 preview。
1配置失败检查 flags、配置字段、路径、adapter/runtime 前置条件。
2收集失败检查 loader 接入、解析错误、key directive/conflict、thread-loader 顺序。
3一般 build failure修复 Webpack 构建本身。
4翻译 item/provider failure阅读 failures；确认 partial vs strict。
5网络翻译未授权交互确认或显式 --allow-network。
6存储事务失败检查磁盘权限/残留 journal；不要手工假定半写入有效。
7strict replacement 有 skipped candidates处理每个 skip 或不用 strict 做有限迁移。

安全边界

  • collect 在 Webpack 单次运行期间阻断网络 primitives，并把 bundle emit 到项目外临时目录。
  • provider 声明 network: true 时，未授权前不能接收源文案；无待翻译项则不提示且不调用。
  • replace --write 与 translate 均使用 journal 事务；失败不是“尽量写多少算多少”。
  • run 固定顺序 collect → translate → replace，且保留首个失败的 code/diagnostic。
