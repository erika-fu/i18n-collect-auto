Webpack 5 接入速查

唯一权威示例是现有 Vue 与 React 配置；请复制结构而不是猜 loader 顺序。

不变量

  1. 每个 compiler 正好实例化一次 new MyI18nPlugin()。
  2. 所有想收集的资源必须真正进入 i18n-collect/myloader；Plugin 不补扫漏网文件。
  3. Collector 要在后续 JS 转换之前，并在 thread-loader 之前运行 pitch。
  4. CSS use 中 Collector 置于最右端，令其先看到 raw CSS。
  5. HTMLWebpackPlugin template 必须强制显式 loader request，且带 force=true。

最小普通 Webpack 形状

const loaderPath = require.resolve('i18n-collect/myloader')
const MyI18nPlugin = require('i18n-collect/myplugin')
const htmlLoader = require.resolve('html-webpack-plugin/lib/loader.js')

module.exports = {
  module: { rules: [
    { test: /\.jsx?$/, use: [loaderPath, babelLoader] },
    { test: /\.css$/, use: [styleLoader, cssLoader, loaderPath] }
  ] },
  plugins: [
    new HtmlWebpackPlugin({
      template: `!!${htmlLoader}?${JSON.stringify({ force: true })}!${loaderPath}!${template}`
    }),
    new MyI18nPlugin()
  ]
}

Webpack normal loaders 从右向左执行；上方数组使 collector 先于 Babel 收集脚本、先于 css-loader 收集 CSS。

Vue 2 / Vue CLI 额外接入点

  • JS rule：把 collector 放在 thread-loader 前。
  • resource query：分别覆盖 type=template、type=script、type=style。
  • CSS rule 的每个有关 oneOf 分支：在 postcss-loader 后（或 css-loader 后）插入 collector，使它处于 raw-input 端。
  • 遍历每个 HtmlWebpackPlugin 实例，重写 template request；不能假设只有一个名为 html 的实例。

配置所有权

Loader fieldsPlugin fields仅配置/translate
include、exclude、contextFilters、attributeAllowlist、styleExtensionsoutputPath、sourceMapFilename、catalogDir、sourceLocale、catalogFormattranslationProvider、targetLocales、translationFailure

把字段传给错误一侧是配置错误。collect 可以临时替换前三个 scope/filter 字段，不能改输出或翻译设定。

排错顺序

  1. 运行配置最终形状测试/检查，不相信注释与链式 API 的直觉。
  2. 确认目标资源实际经过 loader；无 invocation 与无缓存 metadata 会导致“loader is not integrated”。
  3. 确认 HTML request 保留 HWP loader 和 force=true。
  4. 若 watch 多编译一次，先检查是否真实写入官方产物；下一轮相同字节应静默。
