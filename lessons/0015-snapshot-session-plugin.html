一次收集 round 如何从多个 Loader 结果变成文件

Loader 只知道当前资源；Plugin 才知道本次 Compilation 的全局结果。本课解释 snapshot 替换、Module metadata、缓存恢复、Session round 和事务写出的连接。

1. Snapshot 是“一个资源的完整事实”

snapshot = {
  identity: "src/App.vue::template[lang=html]",
  projectPath: "src/App.vue",
  owner: { block: "template", styleIndex: null, lang: "html" },
  entries: [ ... ]
}

一个 Loader invocation 提交的是该 identity 的完整替换 snapshot，不是向全局数组 append。若本次文件删掉了“欢迎”，空 snapshot 就会替换旧 snapshot，使旧文案能够消失。

这也是为什么两个 Vue style block 不能共用 identity：后一次提交会覆盖前一次，而不是合并。

2. record 同时写两条状态链

extractor entries ↓ snapshotFor snapshot ├── module.buildInfo.i18nCollect │ （可由 Webpack cache 恢复） └── session.submit(compilation, module, snapshot) （本轮 candidate round）

record 把普通可序列化 metadata 写到当前 Module。它不是把结果写到磁盘，也不是依赖旧的 Loader Context。

为什么要两份？本轮 Loader 重新执行时，Session 立即有 candidate；未变化模块命中 Webpack filesystem cache 时，Plugin 仍可从 Module metadata 恢复它的 snapshot。

3. Plugin 的生命周期

thisCompilation → session.begin(compilation) ↓ Loader invocations afterSeal → assembleLiveSet(main modules) → assembleLiveSet(child modules) → 检查 metadata / loader evidence ↓ stats 无错误 done → snapshotsForRelease() → retainStaticHtmlSnapshots() → buildCatalog() → 检查 key conflict / reference / ambiguity → session.release(..., writeOutputs)

MyI18nPlugin 的 afterSeal 更适合发现集成诊断；done 只有在 Compilation 成功后才建 catalog 并发布。live 来自当前 Module graph，submitted 来自本轮 Loader，child compiler 的 HTML 还可能需要恢复和有限保留。

4. 为什么失败不能发布半份结果

在正式写文件前可能发生：

  • 其他模块编译失败；
  • 同一个 localization key 对应互不兼容的 message contract；
  • automatic occurrence identity 出现歧义；
  • 未知 localized-call key；
  • 文件写入中途失败。

前几种情况直接 abandon 当前 round，保留上一次正式输出。写入阶段由 output.js 使用 temp、backup 和 journal 成组提交；若中途异常，恢复已替换文件，Session 也用 checkpoint 回滚内存。

candidate round
  ↓ 所有校验通过
release：checkpoint → commit memory → write group
  ├─ 成功：committed + 4 类正式输出更新
  └─ 失败：rollback + previous outputs remain

5. 四类输出不要混淆

输出身份来源用途
zh_hash.jsonMD5(text)兼容旧运行时 dictionary，按文案值去重。
zh_hash.map.jsonMD5 + locations定位来源；不携带 localization key。
catalog/zh.jsonlocalization key翻译与替换的源语言目录。
catalog.meta.jsonoccurrence identity + fingerprint恢复自动 key、记录生命周期与来源。

检索练习

watch 第二轮只重新运行 B 的 Loader，A 命中 filesystem cache；C 已经从当前 Module graph 删除。Plugin 应保留哪些 snapshot？如果 B 的新 snapshot 为空，旧 B 文案是否继续存在？

A 从合法 Module metadata 恢复，B 使用本轮新提交，C 不因旧 committed 而永久保留，会在成功轮次淘汰。B 的空 snapshot 是有效替换，表示 B 当前不再贡献文案，因此旧 B 文案应删除。
