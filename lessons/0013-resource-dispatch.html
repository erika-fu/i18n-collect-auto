NEW SERIES · 02 / 05 · RESOURCE DISPATCH

Loader 如何知道当前应该解析 JS、Vue、HTML 还是 CSS？

Loader 不靠猜文件内容，而是先把 Webpack request 规范化成 Resource，再根据扩展名和 Vue query 选择 extractor。本课建立“请求 → 资源身份 → 解析器”的准确模型。

1. Resource 是什么

resource.js 把 Webpack 的路径和 query 转换成一个纯对象：

{
  absolutePath,
  projectPath,
  query,
  block,
  styleIndex,
  lang,
  sourceOffset,
  identity
}

其中 identity 是 snapshot 的替换边界，不是 localization key。例如：

Webpack 请求Resource identity
src/message.jssrc/message.js::script
src/App.vue?vue&type=templatesrc/App.vue::template[lang=html]
src/App.vue?vue&type=style&index=1&lang=csssrc/App.vue::style[index=1;lang=css]
public/index.htmlpublic/index.html::html

同一 .vue 文件的 script、template、多个 style block 必须拥有不同 identity，否则后提交的 snapshot 会覆盖前一个 block。

2. describeResource 的分派规则

Vue + type=script → block=script, lang=js Vue + type=template → block=template, lang=html Vue + type=style → block=style, index/lang from query JS/TS/JSX extension → block=script .html → block=html configured .css → block=style, index=0 其他 → 无可收集 block

因此 App.vue?vue&type=template&scoped=true&prod=true 中的 scoped 和 prod 不改变收集 identity；真正影响语义的是 block、style index 和 lang。

3. include / exclude 是 Loader 的门

included = include 为空
         或命中任一 include
included = true 且没有命中任何 exclude

exclude 拥有最终否决权。被过滤的资源不会调用 extractor，但仍然会执行 record(..., included=false, snapshot=null)，因此旧 snapshot 能在成功 round 中被清理。

这里有一个设计选择：过滤发生在资源分派之后、解析之前。这样规则匹配的是规范化的项目相对路径，而不是带 query 的 Webpack request。

4. collectedFor 为什么有一个 Vue 特例

普通 JS 可以直接解析 Loader 收到的 source。但 Vue loader 可能已经对 block 做了行填充或去缩进，直接使用 transformed source 会让位置偏离原始 .vue 文件。

所以：

  • Vue script：extractVueScript 读取当前 .vue，遮罩 template/style，只保留 script 的真实行位置，再委托 extractScript。
  • Vue template：extractHtml 读取当前文件，定位唯一匹配的 template block。
  • Vue style：extractCss 读取当前文件，按 style index 定位 block。
  • 外部 <template src> / <style src>：实际提供源码字节的外部资源是位置来源。

这不是目录扫描：Loader 只读取“当前正在处理的资源自身”，Plugin 仍然不读取业务源码。

5. 分派后的三个纯 extractor

Extractor输入主要工具输出 kind
extractScriptJS/TS/JSX 代码Babel parser + traversescript-string、template-literal
extractHtmlVue template / standalone HTMLparse5 + Babel expression parserhtml-text、html-attribute、template-expression 等
extractCss标准 CSSPostCSS + 字符串扫描css-generated-content

它们是纯模块：不访问 Webpack hook、不写输出、不修改 Session。Loader adapter 负责 Webpack 语境，extractor 负责语义识别。

检索练习

同一个 App.vue 有两个 style block：第一个是 CSS，第二个是 SCSS。为什么不能只用 src/App.vue 作为 identity？SCSS 应该让构建失败吗？

两个 block 是两个独立资源；若 identity 相同，第二次提交会覆盖第一个 snapshot。identity 必须包含 style index 和 lang。当前设计不解析 SCSS：提交空 snapshot，并产生一次 unsupported-style-preprocessor warning，不使构建失败。
