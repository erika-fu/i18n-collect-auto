从源码到条目：只认静态、保留语义

目标：能预测一段 JS、Vue、HTML 或 CSS 是否收集、产生什么 semantic kind，以及为什么。

脚本：Babel AST，而非正则或执行

extract-script.js 使用 Babel parser/traverse。普通字符串产生 script-string；反引号字面量的每个静态段分别产生 template-literal。表达式绝不求值，import/export module specifier 被跳过。

const n = 3
const a = '欢迎'        // 收集：script-string “欢迎”
const b = `有${n}条任务` // 收集：template-literal “有”、 “条任务”
import x from '中文包名' // 不收集：不是用户文案位置

可选 contextFilters 只处理脚本候选：logging/tests/analytics 都是精确 AST 上下文策略，默认不启用，避免“看起来不像 UI”就被无声丢弃。

HTML/Vue：结构决定 semantic kind

位置种类关键规则
Vue template 文本html-text每个 text node 独立；格式首尾空白可排除，不跨元素合并。
Vue 白名单属性html-attribute默认仅 title/placeholder/alt/aria-label/value；动态 binding 只取可静态确定片段。
Vue 插值template-expression其中 JS 由 Babel 解析，仍不执行。
独立 HTMLstatic-html-text / static-html-attribute与 Vue 分开，因其运行时/替换含义不同。

parse5 解码 &nbsp; 等 entity 后作为文案值，但 source range 保留原始 spelling；EJS 占位符不执行、不改写。

CSS：非常小的支持面是安全决策

只提取标准 CSS content 声明内的字符串，种类为 css-generated-content：

.badge::after { content: '第' counter(n) '项'; }
/* 收集：“第”、 “项” */
.x { --label: '内部文案'; } /* 不收集：custom property */

这比“收集 CSS 中一切中文”更正确：选择器、注释、变量定义不是可靠的用户可见副本。预处理器没有正式 parser 时仅 warning，宁漏报也不误解析。

指令的关联单位

指令不作用于“下一行任意文本”，而作用于紧随其后的构造：脚本字符串/模板字面量，HTML 元素或 text node，CSS content 声明或其中字符串。它只移除该构造的第一个可收集片段；两个指令锁定同片段也只移除一次。被排除的片段不创建显式 key。

检索练习

以下代码会产生几个条目、分别是什么？
<input :placeholder="'请输入' + name" data-tip="中文">

一个：html-attribute 的“请输入”。:placeholder 归一后在白名单中，且字符串是静态片段；data-tip 不在 allowlist，故即使含中文也不收集。
