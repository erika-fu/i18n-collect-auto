先分类，再提取：为什么每种资源要有自己的 extractor

本课把 runCollect → describeResource → collectedFor → extractor 逐步展开，并解释 Han 门槛、指令和坐标为何属于共享语义。

1. runCollect 不直接猜文件类型

runCollect 首先把 Loader Context 中的两个输入交给 resource.js:66-114：

resourcePath  = /project/src/App.vue
resourceQuery = ?vue&type=template&lang=html

describeResource 负责把它们规范化为一个普通 JavaScript 对象：

{
  absolutePath: '/project/src/App.vue',
  projectPath: 'src/App.vue',
  query: '?vue&type=template&lang=html',
  block: 'template',
  styleIndex: null,
  lang: 'html',
  identity: 'src/App.vue::template[lang=html]'
}

这里的 block 才是分发开关。分类和提取分开，意味着 extractor 不需要了解 Webpack hooks、session 或输出文件。

2. describeResource 怎样分类

输入形状blocklang / indexidentity 示例
src/a.js、.ts 等script普通脚本src/a.js::script
src/page.htmlhtmlHTMLsrc/page.html::html
src/base.cssstyleindex=0, lang=csssrc/base.css::style[index=0;lang=css]
App.vue?vue&type=script&lang=jsscriptjssrc/App.vue::script[lang=js]
App.vue?vue&type=template&lang=htmltemplatehtmlsrc/App.vue::template[lang=html]
App.vue?vue&type=style&index=1&lang=scssstyleindex=1, lang=scsssrc/App.vue::style[index=1;lang=scss]

Vue 的 type query 优先描述语义 block；普通文件则主要由扩展名决定。无关 query（如 id、scoped、prod）不会制造新的 identity；style 的序号和语言会保留，因为它们影响收集语义。

3. collectedFor 的分发树

在 index.js:108-137 中，分发顺序很有意义：

resource.projectPath 是 .vue 且 resource.block === 'script'？ └─ 是 → extractVueScript（定位原始 SFC block，再复用脚本提取） 否则 resource.block === 'template' 或 'html'？ └─ 是 → extractHtml 否则 resource.block === 'script'？ └─ 是 → extractScript 否则 resource.block === 'style'？ └─ 是 → extractCss 否则 └─ null（没有可用 extractor）
extractor负责什么为什么不能全用一个解析器
extractVueScript定位原始 .vue 的 script，再交给脚本语义需要保留 SFC 原始坐标并遮罩其他 block
extractScript字符串字面量和 template literal 静态段需要 Babel AST，且要排除 import/export specifier
extractHtmlHTML/Vue 文本、白名单属性、插值与绑定中的静态段需要 HTML 解析和表达式解析，不能把标签属性当普通 JS
extractCssCSS content: 中的静态字符串需要 CSS AST；普通 CSS 字符串不等于用户可见文案

例如 Vue template 会调用 extractHtml，但 Vue script 不直接调用普通 extractScript：前者需要恢复 template 原始范围，后者需要先定位并遮罩 SFC 外部内容。

4. Han 门槛：候选文案的最低条件

共享函数 resource.js:6-8 是：

function containsHan(value) {
  return typeof value === 'string' && /\p{Script=Han}/u.test(value)
}

它的意思是：一个已经被 extractor 划出的静态片段，只要含有至少一个 Unicode Han 字符，就保留整段；完全没有 Han，就跳过。

片段结果原因
保存成功（2 项）收集完整片段至少含一个 Han；数字、标点、空格也属于同一文案
Hello，保存成功！收集完整片段英文不妨碍，存在 Han 即通过
Hello world跳过没有 Han
class-name跳过通常是技术标识而非中文用户文案

Han 门槛不是“只截取汉字”，也不是完整的语言识别器。它只是这个中文源文案项目的噪声过滤器：先由 extractor 判断语义位置，再由 containsHan 判断该片段是否有理由进入收集结果。

5. i18n-key 是业务键，不是资源身份

在目标片段前面紧邻的注释可以显式命名本地化键：

<!-- i18n-key: home.title -->
<h1>首页</h1>

脚本中使用 JavaScript 注释：

/* i18n-key: order.submit */
const label = '提交'

它只负责命名，不负责排除；要排除文案仍需 no-i18n-auto。没有显式键时，项目会根据项目相对路径、语义种类和文案派生键，且不含行列号，所以在文件内移动同一文案不会仅因坐标变化而换键。

键格式要求以字母开头，由点分隔的段组成，每段可含字母、数字、_ 和 -，如 home.title、order.submit-button。形状错误、同一片段被两条不同 key 命名，都会使本轮失败而不是静默猜测。

三者再对照：resource identity 管“哪份快照”；MD5 管“文本兼容与去重”；i18n-key 管“业务翻译名称”。

6. 提取器返回什么

extractor 是纯模块，不写 session，也不发布文件。它返回条目；Loader 再把条目包装成 snapshot：

entry = {
  value: '首页',
  locations: [{ path, kind, start, end }],
  key: 'home.title' // 只有存在合法 i18n-key 时才有
}

snapshot = {
  identity,
  projectPath,
  owner: { block, styleIndex, lang },
  entries
}

值可能经过 HTML entity 或 CSS escape 解码，但 location 仍指向原始拼写；行号从 1 开始，列号从 0 开始，end 为 exclusive。这就是“用户看到的值”和“开发者编辑的坐标”同时可靠的原因。

检索练习：手动走一次分发

对下面三个请求分别写出 block、extractor 和是否通过 Han 门槛：

1. /project/src/App.vue?vue&type=template&lang=html，内容：<p>Hello，欢迎！</p>
2. /project/src/message.js，内容：const x = 'submit'
3. /project/src/base.css，内容：.x::after { content: '必填'; }

1：template → extractHtml；“Hello，欢迎！”含 Han，收集整段。2：script → extractScript；“submit”没有 Han，跳过。3：style → extractCss；CSS 只检查 content: 的静态字符串，“必填”含 Han，收集。分类先于 Han 判断，Han 不能把技术位置自动变成文案位置。

本课结论：describeResource 负责回答“这是什么语义资源”，collectedFor 负责回答“交给哪个 extractor”，extractor 负责回答“这个语义位置有哪些可收集片段”。
