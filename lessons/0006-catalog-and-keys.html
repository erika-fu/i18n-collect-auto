课程 · 06 / 11 · KEY 模型

稳定身份应被恢复，而非重新计算

catalog key、occurrence 身份、结构锚点与源码位置回答的是四个不同的问题。区分它们，才能让翻译经受住日常编辑，又不会被悄然绑定到错误的 occurrence。

1. 区分四种身份

概念示例回答的问题
本地化 keyauto.01J... 或 order.save运行时/catalog 中对应哪个翻译单元？
Occurrence 身份稳定 ID + 锚点这次出现能否恢复此前的自动 key？
结构锚点宿主 + 角色 + 同级上下文跨轮次时它对应哪一处源码结构？
源码位置Order.vue:5:4..5:6现在的人或 replace 命令能在哪里找到它？
记忆句：key 标识翻译；身份用于恢复 key；锚点匹配结构；位置定位当前文本。

2. 新的自动 key 是不透明的

对于没有相邻 i18n-key 的 occurrence，catalog.js 现在会分配 auto.<ULID>。第一个 key 故意不包含路径、源码文本、行号或列号；它不是可以根据源码复现的摘要。

首次收集
  src/Order.vue，“保存” → auto.01JQ...7K

在其上方插入内容后的后续收集
  相同的结构 occurrence → 复用 auto.01JQ...7K

旧的路径派生自动 key 在迁移旧 metadata 时仍然有效。迁移保留 key；变化的是 metadata 表示，而非运行时身份。

3. Metadata v3 是恢复权威

成功收集会将 metadata v1/v2 升级为 v3。每个 catalog 条目和 occurrence 都记录 representation；版本 2 数据默认获得 source-text。普通自动 key 的恢复权威是 catalog metadata，而非 replacements.json。

catalog.meta.json（v3）
key → source、fingerprint、origin、representation、status
     occurrences[] → id、semanticHost、childRole、
                     localContext、representation、location

旧的 MD5 字典仍会为兼容性按文本值去重；它既不是本地化 key，也不是 occurrence 身份。

4. 仅在历史唯一时复用

  1. 匹配语义宿主，包括安全的一对一宿主移动。
  2. 同级数量一致时，匹配唯一的 sibling:n 上下文。
  3. 对于剩余项目，仅当恰有一个历史 occurrence 和一个当前 occurrence 匹配时，才把源码文本作为辅助证据。
  4. 若仍有多个历史候选可行，不得猜测。

最后一种情况下，收集会分配一个建议的自动 key，写入 identity-ambiguities.json，使本轮失败，并保留所有正式输出。若结构锚点仍匹配，重试会复用该建议，因此确认目标是稳定的。

5. 持久化解决歧义

可通过在源码中添加显式 i18n-key，或在 metadata 旁提交 identity-confirmations.json 来确认歧义 occurrence。确认项会指定 semanticHost、childRole、localContext，以及一个候选 key 或建议 key。所有歧义都确认后，收集才会发布并移除报告。

这种暂停是有意的：产生一条新翻译，也比将已有翻译悄然应用到错误的 UI 文案更安全。

6. 显式共享有契约

显式 key 可以有意聚合多个位置，但每个位置必须拥有相同的消息契约：归一化消息模式以及有序的占位符名称。

i18n-key: greeting
“Hello, {name}”  ✓
“Hello, {user}”  ✗ 占位符契约不同
“Welcome”        ✗ 消息模式不同

key 冲突会在发布前失败并报告所有位置。若显式 key 与自动 key 对应不兼容消息发生碰撞，同样是冲突。

7. 生命周期不是删除

事件Catalog 效果
Occurrence 消失key 变为 orphaned；目标语言翻译保留。
调用引用孤立 keykey 回到 active。
确认退役或 pruneOrphanedkey 离开 metadata；下一次 translate 会清理目标文案/状态。
同一 occurrence 修改源文本key 保留；fingerprint 改变；已有翻译需要审阅。

检索练习

开发者移动一个 occurrence，随后修改其文本。新的自动 key 是否必须包含新路径或新文本？由哪些数据决定是否复用原 key？

不必。新的自动 key 是不透明的；只有 catalog metadata 能通过结构锚点唯一匹配 occurrence 身份时，才会复用既有 key，源码文本仅作辅助证据。文本变化影响 fingerprint 和翻译审阅状态，本身并不定义本地化 key。
