源码替换：保守计划，预览优先

目标：理解 replace 为什么读取 catalog metadata 而非重新收集，以及 adapter 如何保证不会生成无法运行的代码。

replace 的输入是已验证的位置

replace-preview.js 接受 catalog metadata 中的键、原文、位置。它重新读取当前文件、验证 source range/文本仍匹配，再由 Babel/HTML 语境判断是否能编辑。它不重新发现候选文案，因此 collection 和 replacement 的事实边界不混淆。

替换命令可以为 adapter runtime discovery 受限地扫描项目源码；这不同于收集阶段 Plugin 的禁止扫描，因为它的任务正是验证已有 runtime 能力，而非生成 collection。

三种 adapter 都要求现存运行时

adapter生成调用必须先存在的条件
jst('key')项目已有导出名为 t 的函数；不会插 import。
vue2template $t；Options method this.$tvue-i18n 8 且已有 Vue.use(VueI18n) 或 new VueI18n。
vue3template $t；script setup t；Options this.$tvue-i18n ≥9、已有 createI18n，script setup 还需 t 已在作用域。

“不自动插入依赖/启动代码”看似限制，实际避免在不理解项目架构时制造隐性副作用。

安全 skip 与幂等

受限 AST 位置才支持：变量初始化、赋值、return、throw、调用参数、数组元素、对象 value、条件/逻辑/二元/序列式、箭头体、默认导出及相应 template 情形。对象 key、switch case、React JSX、独立 HTML、CSS generated content 都跳过并给理由。

已有 t()、$t()、this.$t() 会被识别而不嵌套，重复运行因而幂等。重叠 edit 也被拒绝。

preview、strict、write

  • 默认：只输出每个文件将写入的 content、replacements、skipped、already localized；零写入。
  • --strict：任一 skipped candidate 退出 7，保证“全部替换或零写入”。
  • --write：准备所有改动源文件、catalog artifacts 和 replacements.json，通过同一 journal 集合提交；失败恢复。

这让迁移先成为可审阅的 diff，再成为可撤销的事务，而非不可控批量重写。

检索练习

为什么 replace --adapter js --write 不替 React JSX 文本，即使 collect 能从 JSX 模块里收集普通字符串？

“能够静态记录文本”与“知道如何把该语义位置安全重写为正确运行时调用”是不同能力。当前 JS adapter 的已证明支持面不包含 JSX text-child/JSX attribute；保守跳过优于生成看似合理却无法验证的 UI/作用域代码。
