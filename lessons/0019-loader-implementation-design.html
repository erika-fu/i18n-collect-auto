一个透明 Loader，七个协作模块：从原始请求到 Resource snapshot

本课逐函数解释 myloader/ 的实现、数据流与设计约束。目标是能够判断某项行为应当修改 Webpack adapter、资源建模、指令规则，还是某一种语义 extractor，而不是把它们都塞进一个 Loader 函数。

1. 先纠正名称：这里只有一个 Webpack Loader

Webpack 的入口是 myloader/index.js 导出的 loader 函数；extract-script.js、extract-html.js 和 extract-css.js 不是 Webpack Loader，而是由该 Loader 调用的纯提取器。它们不访问 Loader Context、不注册 hook、不写文件，也不持有跨编译状态。

模块主要方法职责边界为何这样拆分
index.jspitch、runCollect、recordWebpack adapter、原始资源读取、snapshot 提交把构建框架耦合集中在一个薄层
resource.jsdescribeResource、offsetToPositionrequest 归类、identity、范围和 scope所有 extractor 共用同一套路径/坐标规则
directives.jsscanDirectives、directivesBeforeno-i18n-auto/i18n-key 的语法与关联三种语言不应各自发明 directive 语义
context-filter.jscontextSuppresses可选的 logging/tests/analytics 策略策略是配置，不污染语言解析逻辑
extract-script.jsextractScriptJS/TS/JSX 的 AST 候选Babel 提供准确语义与原始范围
extract-html.jsextractHtmlHTML/Vue template 节点和内嵌表达式同时处理节点边界、entity、Vue 语法和坐标
extract-css.jsextractCss标准 CSS 的 content 静态字符串PostCSS 定位 declaration；小扫描器保留原始 string range
extract-vue-compat.jsextractVueScriptVue script 与完整 SFC 坐标对齐复用 script extractor，不让 Vue 偏移逻辑泄漏进去

这种划分实现了架构记录中的硬边界：Loader 是业务源码的唯一收集入口；Plugin 只恢复、聚合、校验和发布 Loader 已创建的快照，绝不回头解析业务源码。

2. 真实主链：pitch → runCollect → extracted entries → record

loader.pitch()
  └─ fs.readFileSync(resourcePath, 'utf8')
     └─ runCollect(context, originalSource)
        ├─ loadConfig + trackConfig
        ├─ canonicalPair + describeResource
        ├─ isResourceIncluded
        ├─ collectedFor
        │  ├─ extractVueScript / extractScript
        │  ├─ extractHtml
        │  └─ extractCss
        └─ snapshotFor + record
           ├─ module.buildInfo.i18nCollect = serializable metadata
           └─ session.submit(compilation, module, snapshot)

loader normal phase
  └─ callback(null, source, sourceMap, meta)  // transparent pass-through

pitch 优先读取磁盘中的原始字节，因为它发生在 normal Loader 反向转换之前。正常函数仅检查 this.data.collected：已经由 pitch 收集就不再提交第二次；若 pitch 未完成，才使用收到的 source 作后备。

该幂等保护只覆盖一个 Loader request。它不跨越 compilation，也不取代 Session 对多个模块、缓存恢复和失败 round 的管理。

透明性是不变量：myloader 可以增加 metadata、dependency、warning 和收集失败，但不变换编译输入。它把原始的 source、sourceMap 与 meta 原样交给 this.callback，因此收集不会改变 bundle 语义。

3. Adapter 的防御性设计：配置、路径与失败归属

3.1 trackConfig：让 watch 知道配置也是输入

trackConfig 对存在的 i18n-collect.config.js 调用 addDependency，不存在时调用 addMissingDependency。后一种登记很关键：用户后来创建配置文件时，Webpack watch 仍能使相关模块失效。否则配置改变不会触发新的 collection round。

3.2 canonicalPair：优先稳定身份，而非盲目信任字符串路径

它先 path.resolve，再尽力调用 fs.realpathSync。真实路径能消除符号链接造成的“同一文件有两个绝对路径”的身份分裂；文件尚不存在或解析失败时退回 resolved path，避免 Loader 因这一辅助规范化而提前崩溃。

3.3 collectionFailure：把纯函数错误还原为资源诊断

提取器抛出的错误通常携带 error.loc。adapter 将它包装为项目相对路径、block、style index、lang、行和 UTF-16 列。例如 Vue CSS 的语法错误会报告：

i18n-collect failed for src/App.vue, style, index 0, lang css,
line 3, column 14: Unclosed string

提取器因此无需知道如何拼 Webpack 错误信息，而用户仍能直接定位原始源码。

3.4 为什么拒绝 thread-loader

runCollect 发现 loaderContext['thread-loader'] 会 fail closed。收集不仅是计算字符串：它还要写当前 Module metadata 并向主 Compilation 的 Session 提交。Worker 上下文不能可靠地完成这份主进程状态协作，因此正确的修复是把 collector 放在 thread-loader 之前，而非降级为不完整收集。

4. resource.js：将 Webpack request 变成可替换的语义资源

Webpack request 包含物理路径和 query；同一 App.vue 会被 vue-loader 派生成不同的子请求。describeResource 读取扩展名和 URLSearchParams(resourceQuery)，产出统一对象：

{
  projectPath: 'src/App.vue',
  block: 'style',
  styleIndex: 1,
  lang: 'css',
  identity: 'src/App.vue::style[index=1;lang=css]'
}

可忽略的 id、scoped、prod 不进入 identity；会改变收集语义的 block、styleIndex、lang 必须进入。否则第二个 style block 会错误替换第一个 block 的完整 snapshot。

isResourceIncluded 的判断顺序是 include 放行，再由 exclude 否决。它在调用 extractor 前执行，既节省解析，又使 scope 规则只面对规范化、不含 query 的项目相对路径。即便排除，record 仍会记录 invocation 证据；这能使 Plugin 区分“资源被策略排除”与“Loader 根本没有接入”。

offsetToPosition 是跨提取器的坐标权威：行号从 1 起、列从 0 起、按 JavaScript string index 即 UTF-16 code unit 计数，CRLF 只算一个换行。因此 emoji 前的一个字符会占两列；这与编辑器、Babel 位置和可替换 source range 的约定一致。

5. 指令模块：把“邻接”设计成可验证的语法关系

scanDirectives 不把所有注释都当元数据。它只识别两个精确形态：

/* no-i18n-auto */
/* i18n-key: home.title */

第二种先用 KEY_DIRECTIVE 发现以 i18n-key 开头的意图，再用 KEY_DIRECTIVE_SHAPE 和 KEY_SHAPE 完整校验。这个“两阶段”设计使 i18n-key bad 成为 collection failure，而不是被静默当作普通注释；拼写错误不能悄悄改变 catalog 身份。

directivesBefore(source, directives, constructStart, fail) 从构造起点向前回溯。只有 directive 与 directive、directive 与构造之间全是空白，才属于同一组：

/* no-i18n-auto */ /* i18n-key: home.title */ "首页"  // 同组
/* no-i18n-auto */ someCode; "首页"                     // 不关联

它返回 { exclude, key }，并在同组出现不同 key 时立即失败。排除与 key 可以并存，但排除优先：片段根本不会进入 collection result，key 也不会制造 catalog 条目。HTML 与 CSS 各自只负责确定“construct 是什么”，共同的前向关联算法不重复实现。

6. Script 与 context filter：AST 先定义候选，策略后决定是否压制

extractScript 用 @babel/parser 解析 sourceType: 'unambiguous'，并开启 JSX/TypeScript 插件；再用 traverse 访问三类节点：

访问者动作关键排除/结果
CallExpression识别静态 t/$t/this.$t记录 localized-call occurrence，而非重复收集 key 字符串
StringLiteral读取 node.value忽略 import/export module specifier 和 localized-call key；含 Han 才形成 script-string
TemplateLiteral遍历 node.quasis每个静态段独立形成 template-literal；不执行 expression

例如 `你好，${name}！` 产生“你好，”和“！”，不会读取 name。而 "你" + "好" 是两个 StringLiteral，也不会折叠为“你好”。这是刻意的保守语义：自动求值会引入控制流、位置归属和跨语言词序问题。

contextSuppresses 位于 AST 遍历中，但属于独立策略。它只在配置显式选择时过滤静态调用形状：例如最近一层调用为 console.log 才是 logging；console.log(format("界面")) 中“界面”的最近调用是 format，因此仍保留。tests 会向上查找测试调用；analytics 也要求候选实际位于该调用的 arguments 内。可选调用、计算属性和未知形状宁可保留，不进行启发式猜测。

7. HTML 与 CSS：为何“结构解析 + 小范围扫描”优于一个万能正则

7.1 extractHtml 的双层解析

HTML 层使用 parse5 的 sourceCodeLocationInfo，保留 text node、attribute 与 comment 的源偏移；Vue 插值和动态 allowlisted attribute 内的 JavaScript 表达式再交给 Babel。于是同一字符串节点会因语义位置得到不同 kind：

<p>欢迎 {{ '回来' }}</p>
<input :title="'查看' + name">

“欢迎 ” → html-text
“回来”  → template-expression
“查看”  → html-attribute

decodeHtmlText 同时维护解码后的 value 与每个解码单元对应的原始起点。因而 保存&#x540E;关闭 的字典值为“保存后关闭”，但 source range 仍覆盖 &#x540E; 的原始拼写。value 不能反推该范围，所以两者必须在一次扫描中共同产生。

7.2 extractCss 的三段式处理

CSS 层先用 PostCSS 找到 declaration，仅处理 prop === 'content'；随后 declarationValue 找到冒号后的原始 value；最后 scanStrings/readString 扫描 CSS string 并解码 escape。这样既不把 selector、注释、custom property 或普通属性误认为用户文案，也能精确保留字符串内部而不含引号的范围。

.count::after { content: "第" counter(item) "项"; }

"第" → css-generated-content
counter(item) → 动态值，忽略
"项" → css-generated-content

SCSS、Less、Sass、Stylus 不会交给 CSS parser 碰运气。若资源语言不是标准 CSS，函数返回空 entries 和 unsupported-style-preprocessor warning。这个“明确跳过”避免把方言语法解析成看似可信但错误的 collection result。

8. Vue compatibility adapter：复用解析，而不是复制解析

Vue script block 子请求常带有 vue-loader 的填充或转换；直接使用 normal 阶段 source 可能使 Babel 的节点位置无法映射回原始 .vue。extractVueScript 因此读取完整 SFC，找到 script 内容，将 script 前面的非换行字符遮罩为空格：

const code = `${source.slice(0, script.index).replace(/[^\n]/g, ' ')}${script[1]}`
return extractScript({ source: code, resource, config })

保留换行意味着 script 内的行号仍等于原始 SFC 中的行号；遮罩而不是删除前缀意味着列偏移不会左移。然后它完全复用 extractScript 的 AST、directive、localized-call 与 context-filter 规则。

这是一个有意识的局部例外：Loader 只读取当前 resourcePath，用于定位其当前 Vue block；它不递归扫描目录、不会读取其他业务模块，更不会让 Plugin 读源码。若将来 vue-loader 提供稳定的原始 block offset metadata，读取文件可被该 metadata 替换，而 extractor 契约不必改变。

9. 从 entries 到 snapshot：为什么空结果也要提交

snapshot = {
  identity: 'src/App.vue::template[lang=html]',
  projectPath: 'src/App.vue',
  owner: { block: 'template', styleIndex: null, lang: 'html' },
  entries: []
}

snapshotFor 包装的是某个资源当前的完整事实，不是“本次新发现的增量”。所以没有中文、全部被 directive 排除、或标准 CSS 中没有 content 时，空 snapshot 仍有删除旧条目的语义。若之前 template 有“欢迎”，现在没有，提交 entries: [] 才能使该资源的旧贡献消失。

record 同时向两个观察者写信息：

  • module.buildInfo.i18nCollect 保存普通可序列化 metadata，供 Webpack filesystem cache 或下一 compilation 恢复；
  • 当前 compiler 的 CollectionSession 获得本轮即时 submit。若资源被排除或没有 snapshot，则记一次 invocation，而不是假装 Loader 未运行。

这解释了为什么 Loader 不直接写 JSON：它只提交资源级事实；跨资源去重、localization key 身份恢复、catalog contract 冲突和 journal 化的成组写入，都必须在 compilation 成功后由 Plugin/Session 完成。

本课结论：这套实现通过“薄 Webpack adapter + 共享资源/指令策略 + 按语言拆分的纯 extractor”控制复杂度。每一层只拥有一种事实：adapter 知道构建上下文，resource 知道请求身份，extractor 知道语义片段，Session/Plugin 才知道一轮构建能否发布。
