掌握验收（不要只觉得“看懂了”）

  1. 不看答案，画出课程 10 的调用链，并标注哪些阶段能读业务源、哪些不能。
  2. 预测一个带 Vue text、动态 attribute、CSS content、no-i18n-auto 的 fixture 的 entries/kinds/keys。
  3. 解释一次缓存命中时为什么 collection 不丢失，且为什么外来 metadata 不能被使用。
  4. 在临时 fixture 增加一种安全的语义边界，先写失败测试，再最小实现，再跑 package suite。
  5. 执行一次 collect、检查 JSON report，再对同一 fixture 做 replace preview；确认无源码写入后再讨论 --write。

终检索题

请用一句话各自解释：为什么需要 Loader-owned collection、catalog metadata、review state、preview-first replacement？

Loader-owned collection 保留真实构建语义并避免项目扫描；catalog metadata 将键与来源/源版本绑定以可检测演化；review state 保护既有目标译文免受源变更的静默覆盖；preview-first replacement 让潜在破坏性的源码编辑先可见、可审阅、可拒绝。
