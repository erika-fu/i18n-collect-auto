Loader 不是转换器，而是观察者

本课逐行解释 Loader Context、pitch、透明 callback，以及为什么收集要尽早发生但不能改变 bundle。

1. 先区分两种 Loader

转换器 Loader

普通 Loader 的职责是把输入 source 变成另一份 source，供后续 Loader 或 Webpack 使用：

TypeScript：const n: number = 1
       ↓
JavaScript：const n = 1

它改变模块内容，是构建主路径上的加工步骤。

本项目的观察者 Loader

myloader 的目标是发现文案、记录位置和提交 snapshot；它不把源码改成 $t(...)，也不把中文替换成翻译。它走的是一条“观察旁路”：

source ──→ myloader ──→ 同一份 source ──→ 真正的转换 Loader ──→ bundle │ └── entries → snapshot → session / module metadata → Plugin 输出语言文件

所以 myloader/index.js 在普通阶段最终执行：

this.callback(null, source, sourceMap, meta)

四个参数的意思是：没有 error；输出仍是原 source；source map 原样传递；metadata 原样传递。收集结果不进入 bundle，而是进入 session 和 module metadata。

2. this 到底是谁

Webpack 的 loader-runner 调用普通 Loader 时，语义上近似于：

loader.call(loaderContext, source, sourceMap, meta)

因此 Loader 中的 this 是当前模块请求的 Loader Context，不是 Vue 组件实例，也不是 Node 全局对象。

字段 / 方法含义本项目用途
resourcePath当前资源的物理绝对路径读取当前文件原始字节
resourceQuery模块请求的 query辨认 Vue 的 script/template/style
rootContextWebpack 根目录寻找配置并计算项目相对路径
data当前 Loader 的 pitch/normal 共享对象记录 collected 防重复收集
_module当前 Webpack Module写入 buildInfo metadata 以支持缓存恢复
_compilation / _compiler当前 compilation / compiler找到并提交当前 collection session
getOptions()读取 loader 配置取得 root 等选项
addDependency()声明额外依赖配置文件变化能触发构建
callback()结束普通 Loader 调用透明传递 source、sourceMap、meta

因此项目代码使用普通函数而不是箭头函数；箭头函数会捕获定义处的 this，不能接收 Webpack 提供的 Loader Context。

3. pitch 是什么

一个 Loader 可以有普通函数和同名的 pitch 属性：

function loader(source) { /* normal 阶段 */ }
loader.pitch = function pitch() { /* pitch 阶段 */ }

对于一条 Loader 链，Webpack 先运行 pitch，再运行普通函数。简化为：

Loader A → myloader → Loader B

pitch：  A.pitch → myloader.pitch → B.pitch
normal： B(source) → myloader(source) → A(source)

pitch 阶段可以提前观察资源，也可以通过返回值让链路短路；本项目不在 pitch 返回转换结果，而是只调用 runCollect 后继续正常链路。

4. 为什么在 pitch 中读原始文件

普通阶段收到的 source 可能已经经过别的 Loader 处理。项目希望 source map 指向开发者编辑的原始文件，因此在 index.js:182-185 中：

loader.pitch = function pitch() {
  runCollect(this, fs.readFileSync(this.resourcePath, 'utf8'))
  if (this.data) this.data.collected = true
}

这表示：用 resourcePath 找当前资源的磁盘原始字节，交给 runCollect；不把读取结果作为 Loader 输出。

Vue 特别重要：App.vue 可能被 vue-loader 拆成带 query 的请求，template 输入可能去缩进，script/style 可能补行或转换。项目允许 Loader 读取当前正在处理的 resourcePath 自身来恢复原始 block 坐标，但禁止借此扫描其他文件。普通 JS 通常可以直接使用 pitch 看到的 source。

5. 为什么不重复收集

一次 Loader 请求有 pitch 和 normal 两个机会。pitch 成功后把状态写入共享的 this.data：

pitch：this.data.collected = true
normal：if (!this.data || !this.data.collected) runCollect(this, source)

这样正常路径是“pitch 收集一次，normal 透明放行”。如果由于特殊 Loader 链行为 pitch 没执行，normal 阶段才用它收到的 source 作为后备。后备不是第二次收集，而是保证没有 pitch 时仍有机会留下 invocation 和 snapshot。

6. 从 runCollect 回到主流程

runCollect(this, sourceText) 1. 检查 thread-loader，保证在主进程 2. loadConfig + trackConfig 3. canonicalPair + describeResource 4. include 后由 exclude 否决 5. collectedFor 选择 extractor 6. snapshotFor 包装 resource identity / owner / entries 7. record 写 module.buildInfo，并向 session.submit 8. normal 阶段 callback(null, source, sourceMap, meta)

被 include/exclude 排除、没有汉字、或 style 语言不支持时，也会留下 invocation 证据；否则 Plugin 无法区分“Loader 已接入但这次确实没有结果”和“根本没有接入 Loader”。

检索练习：观察者能不能改变源码

假设 myloader.pitch 收集到了“首页”，然后普通函数收到的 source 是原始 Vue 代码。请回答：

  1. this 是什么对象？
  2. 为什么 pitch 可以读取文件，却不会让 bundle 直接变成语言文件？
  3. 哪一行保证 myloader 不修改应用源码？
  4. this.data.collected 防止了什么？

this 是当前模块请求的 Webpack Loader Context；pitch 的读取只是观察和记录，结果通过 session/metadata 旁路交给 Plugin，普通输出仍是源码；this.callback(null, source, sourceMap, meta) 保证透明传递；this.data.collected 防止 pitch 和 normal 阶段重复收集。

本课结论：Loader 的身份由 Webpack 决定，但它的职责可以是观察而非转换。myloader 读取原始资源、提交快照，然后把同一份构建数据放行。
