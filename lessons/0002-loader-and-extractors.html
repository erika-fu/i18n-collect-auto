Loader：唯一的语义入口

目标：理解为何收集发生在 pitch、如何保持透明，以及四个提取器如何分工。

Loader 不是转换器，而是观察者

myloader/index.js 的 pitch 直接读取 resourcePath 的原始字节，再调用 runCollect；普通 loader 函数最终调用：

this.callback(null, source, sourceMap, meta)

这保证收集不会改变 bundle。this.data.collected 防止 pitch 与正常阶段重复收集；若 pitch 没执行，正常阶段才以其收到的 source 作为后备。

它必须在后续脚本转换之前、且在 thread-loader 之前：worker 无法可靠地写主进程 compilation/session，因此代码会明确报错而不是产生不完整结果。

一次 Loader 调用的精确路径

pitch → runCollect → loadConfig + trackConfig → canonicalPair + describeResource → isResourceIncluded（include 后由 exclude 否决） → collectedFor（按 block 分派 extractor） → snapshotFor → record（module.buildInfo + session.submit） → 普通阶段透明 callback

被排除、无中文、或不支持的 style 也留下 invocation 证据；否则 Plugin 无法区分“已接入但结果为空”与“忘记接 Loader”。

资源分类与 extractor

资源提取器收集内容
JS/TS/JSXextractScript非 import/export specifier 的字符串、template literal 的静态 Han 段。
Vue scriptextractVueScript定位并遮罩 SFC 外部字符以保持源码坐标，然后复用脚本提取。
Vue template / HTMLextractHtml文本、白名单属性、插值、动态绑定中的静态片段；解析不执行。
CSS / Vue styleextractCss仅 content: 声明中的静态字符串。SCSS 等产生一次 warning 与空快照。

提取器是纯模块：不触碰 Webpack hooks、session 或输出。这样可用小 fixture 精确测试语义与坐标。

三项共享语义

  1. Han 门槛：containsHan 用 Unicode Han Script 判断；一段只要含一个 Han，整段静态文本保留。
  2. 指令：紧邻且只隔空白的 no-i18n-auto 排除下一个关联片段；i18n-key: a.b 提供显式键。畸形 key 与同片段不同 key 是收集失败。
  3. 位置：值可经 HTML entity/CSS escape 解码，范围仍锚定原始拼写；行 1-based、列 0-based UTF-16、end exclusive。

检索练习

为何 Vue block 的收集器再次读取当前 .vue 文件，而普通 JS 通常直接使用 loader 的 source？

vue-loader 的 block 输入可能被去缩进、填充或转换，无法稳定恢复原始列。重新读取当前正在处理的 SFC 是为原始坐标的最小例外，不是 Plugin 扫描，更不是跨文件收集。普通脚本的 pitch 已拿到原始字节，无需此例外。
