先建立正确的系统地图

目标：用四个阶段和三个身份解释整个项目，避免把它误读成“扫一遍源码的脚本”。

一个迁移管线，四个刻意分离的阶段

Webpack source resource ↓ myloader（识别并提交快照；不改源码） MyI18nPlugin（汇总一轮；原子发布） ↓ source-locale catalog translate（可选，项目 provider 生成目标目录） ↓ keyed catalogs + review state replace（可选，默认预览；--write 才改源码）

这条分层的核心是可逆与可验证：收集不能因为翻译服务或替换风险而失败；翻译不能修改应用；替换必须先展示将发生什么。

三种身份绝不可混淆

身份例子用途
资源身份src/App.vue::template[lang=html]决定哪份快照替换哪份旧快照。
文本 hashmd5('欢迎')兼容既有运行时字典，按文本值去重。
本地化键home.welcome翻译目录与替换调用的稳定语义标识。

因此：仅改 i18n-key 会改 catalog 而不必改 MD5 字典；移动同一文本通常不改派生 key，因为 key 不含坐标。

仓库构成

  • packages/i18n-collect：CommonJS 核心包、Webpack 5 peer dependency、CLI 与 Node 测试。
  • apps/demo：Vue 2 + Vue I18n 8 + Vue CLI 集成范例。
  • apps/react-demo：React 18 + 独立 Webpack 5 集成范例。
  • docs/：README 是行为契约；架构文档说明收集设计；故障文档解释运行现象。

检索练习（2 分钟）

若一个文件从 Webpack module graph 移除，为什么不能只“向集合追加新文本”？

因为旧文本会永久残留。每个 resource identity 必须提交完整替换快照，Plugin 又以当前 module graph 构造 live set，才能自然淘汰删除文件、移除 import、删除 Vue block 或过滤规则改变后不再存活的文案。

本课结论：项目的最小理解单元不是“字符串”，而是“一个 resource snapshot 在一个 collection round 中被验证并发布”。
