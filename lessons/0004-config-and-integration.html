接入：让语义资源真正经过 Loader

目标：能独立配置 Webpack 5/Vue 2，理解严格配置与 loader 顺序背后的正确性条件。

配置是单一权威，但字段有所有者

config.js 用默认值 + i18n-collect.config.js + 受限显式 options 合并。字段归属是防止“看似生效，实际某层从未读取”的设计：

LoaderPluginTranslate
scope、属性白名单、style 扩展名hash 输出、map 输出、catalog 位置/源 locale/格式provider、目标 locale、partial/strict

validate 拒绝未知字段、重复/越根 glob、绝对路径、重叠官方产物及无效 locale。严格失败优于默默采用危险默认值。

两枚 hash 解决缓存与产物的不同问题

  • fileConfigHash：仅来自配置文件的收集字段，写入 module metadata；用于判断缓存快照能否归属当前 root/config。
  • configHash：纳入本次 loader/plugin/CLI collect 覆盖后的收集设定，写进 source map。

两者均排除 catalog/translation fields：只移动 catalog 目录或变更 provider 不应让语义快照失效，也不应无端改变 source map。

Webpack 接入为何精细

通过 require.resolve 获取 loader；Plugin 仅实例化一次。Vue 项目还要把 Loader 接到 JS、Vue template/script/style 与 HTMLWebpackPlugin 模板链。普通 HTML rule 不够，因为 HTMLWebpackPlugin 自己编译 template。

html-webpack-plugin/lib/loader.js?force=true
  ! i18n-collect/myloader
  ! public/index.html

force=true 避免 HWP 见到其他 loader 后跳过自身，否则 EJS 标记不会展开。Collector 原样返回输入，所以后续 HWP 仍完成资产注入。

Include/exclude 不是普通字符串匹配

无通配符模式是目录/文件边界：src/foo 匹配自身与 src/foo/a.js，但不匹配 src/foobar.js。有元字符才是受限 glob；exclude 无论与 include 如何重叠，始终最终否决。此限制保障跨平台可预测性与项目根安全。

检索练习

为什么项目不能只添加 Plugin、让 Plugin 递归扫描 src 来“自动发现”文案？

这会绕过真实 module graph、loader 顺序、include/exclude、Vue block 语义、缓存和 child compilation，并使未参与构建的孤儿文件污染结果。该架构选择“Loader 是唯一创建 snapshot 的地方”；无 Loader 证据被视为接入错误，而不是让 Plugin 不可靠地补救。

实操：接入前后先阅读 Webpack 接入速查，再以 loader-order 测试 验证最终规则，而不是仅看配置注释。
