NEW SERIES · 03 / 05 · EXTRACTION SEMANTICS

不是“找到中文就收集”：三个 extractor 的实现方法

本课通过最小例子说明 AST、HTML 节点和 CSS declaration 各自怎样产出 entry，并解释为什么动态表达式不执行、为什么一个模板字面量可能产生多个 entry。

1. Script：Babel AST 上的静态候选

const a = "欢迎"
const b = `你好，${name}！`
const c = "English"
import x from "中文模块路径"
console.log("日志中文")

extract-script.js 首先调用 Babel：

const ast = parser.parse(source, {
  sourceType: 'unambiguous',
  plugins: ['jsx', 'typescript']
})
traverse(ast, { StringLiteral() {}, TemplateLiteral() {} })

这里的 AST 是“源码的结构化语法树”，不是把源码按正则切成字符串。Babel 会把上面的不同构造区分成不同节点。提取器只读取节点的静态字段和值，不执行程序。

源码构造AST / 字段提取结果
"欢迎"StringLiteral.node.value === '欢迎'，有 start/endscript-string，一个 entry
`你好，${name}！`TemplateLiteral.node.quasis 有两个静态 quasi；expressions 有一个 name“你好，”和“！”分别是两个 template-literal entry
"English"仍是 StringLiteral没有 Han 字符，不收集
import x from "中文模块路径"StringLiteral 的父节点是 module specifier按父节点排除，不当用户文案

1.1 中文识别不是“只保留中文字符”

containsHan(value) 实际使用 /\p{Script=Han}/u 判断片段中是否至少有一个 Han 字符。只要命中，整个静态片段都保留：

"你好，123 ABC"  → 收集完整片段
"，。！"          → 不收集
"hello"           → 不收集
"𠀀"              → 收集（扩展 Han）

因此它不会把“你好，123 ABC”再拆成“你好”和“123 ABC”；entry 的 value 是 AST 解码后的完整静态值，location 则来自 AST 的原始范围。

1.2 最重要的策略：不执行、不求值、不自动拼接

const a = "你好"
const b = `前缀${name}后缀`
const c = "你" + missing + "好"
const d = "你" + "好"
const e = `前${"内嵌"}后`

当前实现的结果可以写成：

源码结果原因
"你好"一个 你好一个 StringLiteral 节点
`前缀${name}后缀`前缀、后缀只取两个 quasi；不读取 name
"你" + missing + "好"你、好只访问两个 StringLiteral；不执行 missing
"你" + "好"你、好即使两边都静态，也不做常量折叠
`前${"内嵌"}后`前、内嵌、后外层 quasi 是 template-literal，内层 StringLiteral 是 script-string

所以项目没有“拼接策略”来生成最终运行时字符串。这是有意的边界：自动拼接需要执行表达式、求变量值或猜测控制流，既可能不安全，也无法可靠地给每一段建立原始 location。项目选择“可静态证明的片段独立收集”，后续翻译和运行时格式化再处理动态参数。

1.3 semantic kind 从哪里来

kind 不是根据 value 猜的，而是由“节点所在的语义位置”决定：

  • JS/TS 文件中的 StringLiteral：script-string。
  • JS/TS 文件中的模板 quasi：template-literal。
  • Vue template 的 {{ '中文' }}：HTML extractor 解析表达式时显式传入 template-expression。
  • 动态 HTML attribute 的 :title="'查看' + name"：静态字符串仍属于 html-attribute，不是 script-string。

也就是说，同样是 Babel 的 StringLiteral，它在普通 JS 文件和 Vue attribute 表达式中可能得到不同 kind；kind 描述的是来源语义，不只是 AST 节点名称。

静态 t('key')、$t('key')、this.$t('key') 会先被识别为 localized-call，其 key 是已有的运行时引用，不会再被当成待收集的源文本。

2. HTML：先保留节点边界，再解析表达式

<button title="保存后关闭">保存</button>
<p>欢迎，{{ name }}！</p>
<input :placeholder="'请输入' + fieldName">

extract-html.js 用 parse5 得到带 source location 的节点：

  • 文本节点独立收集，不跨越标签合并；“保存”是 html-text。
  • 白名单属性（如 title、placeholder）收集完整静态值；“保存后关闭”是 html-attribute。
  • Vue 插值中的表达式交给 Babel；动态值不执行，只收集其中静态 string/template fragment。“请输入”是 html-attribute，而普通文本和表达式的 semantic kind 不同。
  • {{ name }} 本身不是中文候选，不会产生 entry。

HTML entity 使用解码后的值判断和计算 MD5，但 location 仍指向原始拼写，例如 &#x540E;。

3. CSS：只看 content declaration

.badge::before { content: "必填"; }
.count::after { content: "第" counter(item) "项"; }
.card { color: "中文"; }
.note { --label: "内部文案"; }

extract-css.js 使用 PostCSS 遍历 declaration，只处理属性名为 content 的声明：

  • “必填”生成一个 css-generated-content entry。
  • “第”和“项”是两个独立静态字符串，各生成一个 entry。
  • counter(item)、var(...)、选择器、普通 declaration 和 custom property 不收集。
  • 空字符串、空白、none、normal 忽略；SCSS/Less 等当前只 warning。

CSS escape 先解码得到最终值，但 source range 仍覆盖原始 string 内容，不包括引号。

4. 指令如何改变“下一个候选”

// no-i18n-auto
const title = "首页"

/* i18n-key: home.title */
const welcome = "欢迎"

directives.js 的思路不是全局开关，而是“只向前关联、只关联空白相隔的一组指令”。

  • no-i18n-auto 排除紧邻 construct 的一个候选；它自己不被收集。
  • i18n-key: home.title 为对应候选提供显式 key。
  • 普通注释无语义；格式错误的 i18n-key... 会使本轮失败，而不是被静默忽略。
  • 同一组中出现两个不同 key 也失败，避免一个片段拥有不确定身份。

检索练习

模板字面量 `前缀 ${value} 后缀` 会不会把整个字符串当成一条文案？动态属性 :title="'查看' + name" 是否需要执行 Vue 表达式才能收集？

不会。模板字面量的每个静态 quasi 独立判断，因此得到“前缀”和“后缀”，插值表达式不收集。动态属性也不执行表达式；Babel 只解析语法，静态字符串“查看”直接成为 fragment。
